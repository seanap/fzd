# FZD v2.1.0 — At home on Linux and Omarchy

FZD combines fzf, zoxide and plocate with rich previews and shell navigation.
This release adds conditional Omarchy integration and a simpler installer while
preserving the familiar `lf`, `lf name` and `lff name` workflow.

## What's new

- **Simple and Enhanced installation.** `bash install.sh` installs the standard
  experience; `--enhanced` also sets up missing optional preview tools, a suitable
  clipboard provider, inline suggestions and font conveniences. Existing tools
  activate in either mode. Lazygit is never installed automatically.
- **Omarchy integration.** Session colors follow the active palette, explicit
  FZD overrides take precedence, and argument-bearing editors such as
  `omarchy-launch-editor --inline` work safely. An optional Bash launcher retains
  the selected directory in an interactive shell.
- **Richer previews.** eza is a standard recommendation with reliable captured
  icons and an explicit icon opt-out. Chafa renders images and Glow renders
  Markdown when available, with bounded work and existing fallbacks.
- **Contextual actions.** Alt+Y copies the highlighted absolute path through
  Wayland or X11 providers. Alt+G opens an existing Git working tree in Lazygit
  when installed, then restores the browsing session.
- **Respectful setup and upgrades.** Dedicated user-editable XDG shell files
  keep startup entries minimal. Managed v2.0 blocks migrate safely; existing
  aliases, hooks, completion handlers, themes and inline preferences remain.
  Runtime directory validation, private temporary storage, rollback and owned
  file removal protect existing installations.

## Install and upgrade

Run as your normal user:

```bash
git clone --branch v2.1.0 https://github.com/seanap/fzd.git
cd fzd
bash install.sh --enhanced
```

Plain `bash install.sh` provides the full standard experience without optional
shell-wide enhancements. Open a new terminal after installation. For an existing
source installation, use a fresh release checkout and rerun the installer with
your existing prefix and shell options. Simple updates preserve an existing
Enhanced inline preference.

**plocate is now required.** Both modes also attempt recommended eza, fd, bat,
file and tree packages. If plocate is missing, review the distribution's indexing
policy first: FZD stops before installing its package unless you explicitly add
`--allow-package-indexing`. Package setup may initialize a database or enable an
indexing schedule. FZD itself never runs updatedb or changes indexing exclusions.
Existing plocate installations need no additional authorization.

Ubuntu/Debian users can download the `.deb`, `SHA256SUMS` and `SOURCE`, then run:

```bash
sha256sum --ignore-missing -c SHA256SUMS
cat SOURCE
sudo apt install ./fzd-2.1.0-debian-all.deb
```

Arch users can build the checksum-pinned `PKGBUILD` with `makepkg -si`. Packages
leave user startup files untouched; source the packaged integration explicitly
as described in the technical guide. No AUR publication is claimed.

## Validation and platform limits

The implementation passed both hosted fzf regression configurations, static
checks, reproducible builds, and Ubuntu, Debian, Arch and Fedora userspace
validation. Fedora coverage is staged runtime compatibility, not an RPM
lifecycle test. Release preparation requires the same workflow to pass on the
final release revision before publication.

Normal startup benchmark medians changed by approximately 0–8 ms; measured
preview differences remained small. Conditional Omarchy palette setup added
approximately 3–61 ms in the retained fixture benchmarks. Measurements and
methodology are in `benchmarks/results/omarchy/`.

Native Omarchy desktop appearance, terminal font selection, real compositor
clipboard access, and actual Glow/Lazygit UIs remain manual validation items.
Installed fonts do not prove that the terminal uses them. On WSL, configure a
compatible font on Windows; Linux-side font installation cannot configure
Windows Terminal. The optional Omarchy launcher currently supports Bash;
ordinary zsh shell integration remains supported.

See `docs/TECHNICAL.md`, `docs/packaging.md` and
`docs/validation/omarchy/README.md` in the source archive for detailed setup,
dependency policy, test evidence and remaining limitations.
